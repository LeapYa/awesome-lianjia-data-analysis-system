# 账号池与登录后采集

链家翻页、成交页现在要求登录，验证码这一关我们能自动过，账号这一关要处理。这套东西就干两件事：**把登录态存下来复用**，**让采集带着登录态跑**。

## 文件分工

| 文件 | 作用 |
| --- | --- |
| `account_manager.py` | 账号池（SQLite）：增删、登录、Cookie 缓存、有效性检测 |
| `login_session.py` | 登录状态机：密码 → 滑块 → 短信码 → v4 点选，人工只管填短信码 |
| `slider_solver.py` | 滑块：读 canvas 找缺口 + 拟人轨迹拖动 |
| `slider_probe.py` | 滑块试探脚本：每次尝试存图、存位移、存结果，用来攒样本 |
| `lianjia_collect.py` | 采集：带 Cookie 抓列表页，遇验证码自动解 |
| `async_crawler.py` | 多账号多 IP 异步采集 |
| `admin_server.py` | 管理后台：账号、代理、启动采集 |

## 账号池

数据存在 `data/accounts.db`（不入库）。表结构：

```
accounts(id, phone, password, storage_state, cookies, status, note,
         last_login, last_check)
proxies(id, url, enabled, fails, last_ok)
```

`status` 取值：`unknown` / `ok` / `expired` / `needs_manual` / `failed`。

```python
import account_manager as am
aid = am.add_account("手机号", "密码", "备注")
am.login(aid)          # 自动走登录；需要短信码时会返回 needs_manual
am.check(aid)          # 用缓存 Cookie 访问第 2 页，判断登录态是否有效
```

## 登录：四道关，人工只管一道

```
1 手机号 + 密码       程序填
2 点「获取验证码」滑块   slider_solver 自动过
3 6 位短信码          人工（短信在手机上）
4 提交时的 v4 点选     record_lianjia 的 solver 自动过
```

`login_session.LoginSession` 是个状态机，能挂后台：

```
POST /api/accounts/{id}/login/start    启动
GET  /api/accounts/{id}/login/status   轮询（need_sms 为真就弹输入框）
POST /api/accounts/{id}/login/sms      提交短信码
```

不想自动，也可以走 `POST /api/accounts/{id}/login/manual`：开有头浏览器，全部人工完成，离开登录页即保存 Cookie。**实测这条路最稳**，滑块自动化还在调。

## 滑块

`slider_solver.py` 里三条路，按可靠性排序：

1. `solve_slider_canvas`：读 `geetest_canvas_bg` 与 `geetest_canvas_slice` 的像素，用 slice 的 alpha 当模板，在 bg 上做带掩码匹配，三种方法（彩色 / 灰度 / 边缘）投票定位缺口
2. `solve_slider_screenshot`：截面板元素，用饱和度找拼图块，边缘模板匹配找缺口
3. `solve_slider_retry`：从 background-image 取图，v3 时代的像素差分法

轨迹用的是一次“靠近 → 按住停顿 → 分段变速 → 中途停两次 → 末端越过 2px 回位”，比匀速直线更接近人手。

已知问题：位移算得准的时候，站点仍可能判定为机器（出现过“怪兽吃掉拼图”的提示），说明行为特征还差一些；另外 canvas 回读有时拿到旧帧，导致连续几次算出同一个距离。要调这两点，需要真值样本，用 `slider_probe.py` 攒：

```bash
python slider_probe.py --tries 10
# data/slider_log/<时间戳>/try_XX/{00_bg.png, 01_slice.png, 02_curve.json, result.txt}
```

## 采集

带账号 Cookie 抓多城市多页：

```bash
python lianjia_collect.py --city bj,sh,gz --pages 2-4 --kind ershoufang \
    --account 2 --out data/multi_page.jsonl
```

单页 30 条，中途遇到 v4 点选会自动解。实测 bj/sh/gz 各 2~4 页，270 条，登录墙已绕过。

多账号多 IP 异步版：

```bash
python async_crawler.py --cities bj,sh,gz --pages 2-4 --workers 3 --out data/crawl_async.jsonl
```

worker 之间按账号和代理分工，遇登录墙把账号标 expired 并换号重试，代理连续失败三次自动停用。

## 管理后台

```bash
python admin_server.py --port 8897
# 打开 http://127.0.0.1:8897/
```

页面里能加账号、点登录（弹短信框）、检测 Cookie、加代理、启动采集并看进度。

## 注意事项

- `data/accounts.db` 存了明文密码，别提交、别外传
- 采集频率别拉满，翻页之间留 1 秒以上，验证码触发会少很多
- Cookie 有效期不固定，`am.check()` 每小时跑一次，失效了再人工登一次

## 模型就在本仓库

识别代码 `geetest_solver/` 和模型 `models/` 都在项目里，直接 `import geetest_solver` 就能用，不需要额外克隆仓库或配环境变量。

`models/` 清单（共约 35MB）：

| 文件 | 体积 | 用途 |
| --- | --- | --- |
| `detector_v26.onnx` | 9.3MB | 字框检测 |
| `ocr_tiny_w96.onnx` | 4.2MB | 单字识别 |
| `ppocrv6_tiny_dict.txt` | 30KB | 字符表，必须和 OCR 配套 |
| `order_lm_small.pkl` | 10.8MB | 3 字语序 n-gram |
| `order_ranker.npz` | 5.1MB | 3 字语序分类器 |
| `jieba_dict.txt` | 4.8MB | 谓宾语序词表 |
| `query_lib.pkl` | 1.0MB | 形状模板库 |
| `geetest.pkl` | 3.1MB | 旧模板库，回退用 |

部署时只要把整个仓库拉下来，`GeetestSolver()` 会从 `models/` 读模型，路径由 `geetest_solver/solver.py` 里的 `MODEL_DIR` 决定，不依赖任何环境变量。
